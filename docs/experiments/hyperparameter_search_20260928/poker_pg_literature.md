# Poker policy-gradient literature survey

Bounded survey prepared 2026-09-28 for selecting baselines for heads-up NLHE at
32 bb. It covers primary papers and a small amount of directly associated code;
it is not an exhaustive bibliography. “Eligible” means that a learned policy is
trained end to end with an online policy-gradient or actor-critic objective.
CFR, regret matching, search-only, and value-only methods are separated from
plain policy-gradient baselines even when they are strong poker systems.

## Reward contract for this project

For a two-player, equal-stack 32 bb hand, use terminal zero-sum utility

`u_i = (final_stack_i - initial_stack_i) / 32`.

With correct pot splitting and no rake, this gives `u_i ∈ [-1, +1]` and
`u_1 + u_2 = 0`. Set all intermediate rewards to zero and use `gamma = 1` if
the objective is undiscounted hand equity. GAE lambda is a variance-control
parameter and does not change this reward definition. Advantage normalization is
compatible with the contract; streaming Z-normalization of rewards is not.

This mapping is an adaptation recommendation, not a claim about the source
implementations. Most papers below report chips, BB/hand, or an environment
reward without specifying a fixed normalization. Any action-cost shaping must be
removed or folded into the terminal net-stack utility before claiming the
`[-1, +1]` contract.

## Adjacent or excluded methods

- **DeepNash / R-NaD** ([DeepNash paper](https://arxiv.org/abs/2206.15378)) is a Stratego system, not a poker policy-training result. Its regularized Nash dynamics are relevant to the broad policy-optimization literature but provide no NLHE reward or hyperparameters for this target.
- **ESCHER** ([paper](https://arxiv.org/abs/2206.04122), [code](https://github.com/Sandholm-Lab/ESCHER)) is regret learning with sampled traversals and regret matching. It is not a plain end-to-end policy-gradient baseline.
- **Deep CFR, DREAM, DeepStack, Libratus, Pluribus, ReBeL, and Player of Games** use CFR/regret targets and/or explicit search. They are valuable poker strength references but are outside this PG survey. ReBeL in particular couples learning to continual subgame solving, so it should not be treated as an end-to-end policy-only recipe.
- **ACH** ([ICLR paper](https://openreview.net/pdf?id=DTXZqTNV5nW), [poker code](https://github.com/Liuweiming/ACH_poker/blob/main/ach.sh)) and **NeuRD** ([primary paper](https://arxiv.org/abs/1906.00190), [associated FHP scripts](https://github.com/Liuweiming/ACH_poker/blob/main/neurd.sh)) deserve separate treatment. ACH is a model-free actor-critic/Hedge implementation of neural weighted CFR, so it is policy optimization adjacent rather than plain PPO. Its OpenSpiel table includes heads-up Flop Hold’em Poker (FHP), and the associated `ach.sh` uses LR **1e-4**, regret replay memory **1,000,000**, policy memory **10,000,000**, CFR batch **1000**, train batch **128**, one regret-network train step, **16** policy train steps, `ach_alpha = 2`, `ach_beta = .03`, threshold **2**, reward scale **.002**, and `sync_period = 1`; `neurd.sh` uses the same FHP harness with two regret-network steps, one policy step, `ach_beta = .05`, and the same LR/other settings. FHP is a betting abstraction, not full NLHE. The NeuRD paper itself evaluates Kuhn and Leduc, with constant step sizes swept over `{0.5, 0.9, 1, 1.5, 2, 2.5, 3, 3.5, 4}`; it reports no 32 bb/full-NLHE reward mapping. These are useful adjacent ablations, not drop-in HU NLHE defaults.
- **ARMAC** ([primary paper](https://arxiv.org/abs/2008.12234)) is also regret-matching policy improvement rather than plain policy gradient. Its FCPA betting-abstracted no-limit Hold’em run used `{Fold, Call, Pot, All-in}`, one GPU, 18 days, 1.3B acting steps, 5M learning steps, and 50,000 CFR epochs, reaching an LBR-FC score of `-46 ± 26` per episode (95% CI). The paper does not provide a directly transferable normalized 32 bb optimizer recipe.
- The 2026 policy-gradient reproducibility study ([paper](https://arxiv.org/pdf/2502.08938)) evaluates PPO, PPG, MMD, and R-NaD on Liar’s Dice, Dark Hex, and Phantom Tic-Tac-Toe variants, not poker; it supplies no poker hyperparameters.

## Practical shortlist for the 32 bb HU sweep

For continuity, start with the known July AdamW LR `5e-5`, then test `1e-4` as
the first higher-LR arm. AlphaHoldem’s Adam `3e-4`, large rollout batch (scale
its 16,384 effective batch to available hardware), and GAE `0.95` are a later
transfer candidate, not the default for this checkpoint continuation. Change
the objective explicitly: terminal net stack change / 32, intermediate zero
rewards, and `gamma = 1`. Use a positive entropy coefficient at the start of a
planned decay schedule, make it exactly `0` after the selected horizon, and
include a zero arm for the trained-checkpoint continuation.
AlphaHoldem’s dynamic chip-based value clips should be treated as unknown until
the implementation is inspected; do not silently copy a chip scale after
normalizing rewards. The NeurIPS actor-critic study is a useful small-game diagnostic, but its
SGD/`gamma=.99`/entropy `.1` configuration should not be presented as a
normalized-HUNL recommendation. AlphaExploitem’s AdamW `1e-4` and league
schedule are an alternative league baseline, with entropy decayed to zero and
its unreported KL threshold left disabled.

“Entropy disappears” here means the entropy bonus coefficient is scheduled to
zero over training; it does not require a deterministic policy during the
decay. If a separate evaluation arm requires deterministic behavior, evaluate
with argmax after training. Epsilon-greedy/action noise is a separate behavior
exploration choice and should be recorded independently.
