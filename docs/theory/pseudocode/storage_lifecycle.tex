\section{Authority and exactness boundary}

This is the implementation companion to \texttt{core\_math.tex}.  Scheduling,
layout, streaming, and recomputation policy may change; the sampled
rollout law, completion estimators, $\lambda$-returns, posterior-weighted
surrogates, clipping, entropy, reference KL, and distributed decision law may
not.  The algorithms in this directory must deliver the same mathematical
arguments to every production loss.  Production implements the clipped PPO
policy surrogate, value regression with optional value clipping, entropy,
legal-action KL to a frozen reference, and the public trace-variance/cost heads
used by fixed or dynamic KKT branching.  It deliberately defers a separately
stored $Q$ target/loss, RNaD/NeuRD, and $W/S$ auxiliaries.  Dynamic branching,
nominal-versus-executed offspring correction, and protected-cohort root refill
are current requirements from \texttt{core\_math.tex}; their minimal retained
and transient fields are specified below rather than inferred from a legacy
tree representation.

Each partition has an exact loss domain $\mathcal X_m$, a natural model-row
domain $\mathcal Y_m$, and a fixed architecture map
$\varphi_m:\mathcal X_m\to\mathcal Y_m$.  Model inputs and outputs are stored
directly on $\mathcal Y_m$.  Whenever a loss is summed over an exact private
state $x\in\mathcal X_m$, it reads the corresponding model row
$\varphi_m(x)$:
\[
 V^\theta(x,\sigma)=V^\theta_m[\varphi_m(x),\sigma],
 \qquad
 \log\pi^\theta(a\mid x,\sigma)
 =\log\pi^\theta_m[a,\varphi_m(x),\sigma].
\]
Usually $\mathcal X_m=\mathcal Y_m$ and $\varphi_m$ is the identity.  The
stored arrays are simply the model's own arrays on $\mathcal Y_m$.
Posterior, return, and advantage arrays remain on
$\mathcal X_m$ because aggregating them is generally not loss-preserving under
nonlinear PPO and value clipping.

All decisions routed to one partition must use the same canonical ordered
exact-state domain $\mathcal X_m$.  The meaning and row order of $x$ may not
depend on a particular decision, board, owner, or physical batch.  Impossible
states have zero posterior mass.  A game must split a partition if it cannot
supply this invariant; core never infers or repairs a decision-local domain.

\section{Game-neutral partition interface}

The core sees only a finite collection of immutable \Obj{PartitionSpec}
objects.  A specification contains
\begin{center}
\begin{tabular}{p{0.27\textwidth}p{0.64\textwidth}}
\toprule
Member & Contract \\
\midrule
$m$, diagnostic name & Stable integer identity; the name is never parsed by core. \\
$\kappa(\sigma)$ & Pure public-state router for player nodes. \\
$\preceq$ & Optional preorder used only to choose among otherwise eligible queues. \\
$X_m=|\mathcal X_m|$ & Exact private-state width used by targets and losses. \\
$Y_m=|\mathcal Y_m|$, $\varphi_m$ & Natural model-row width and fixed exact-state-to-model-row lookup. \\
input/model layout & Natural partition input and curried policy/value forward on $\mathcal Y_m$. \\
byte/work contract & Fixed worst-case retained bytes per row, transient bytes per physical pack, safe row limits, and legal batch quanta. \\

\end{tabular}
\end{center}
Core may route, queue, account, sample, and batch by $m$.  It may not inspect a
game stage, synthesize a subpartition, or reorder rows by an undeclared public
label.  The default scheduler is full-batch first; within the set of full
queues it chooses a minimal preorder layer, then load and age.  A forced partial
drain also starts in the minimal nonempty layer.  With an empty preorder all
partitions are incomparable.

\section{Poker application of the abstract interface}

Poker supplies exactly
\[
  \mathcal M=\{\mathsf{pre}\}\sqcup
  \{\mathsf{post}_A:2\leq A\leq P\},
  \qquad \mathsf{pre}\prec\mathsf{post}_A,
\]
with the $\mathsf{post}_A$ mutually incomparable.  The public board and betting
history remain opaque input fields.  Flop, turn, and river with the same $A$
are one partition, use the same fixed dense hand width, and are not sorted,
split, packed, or assigned different physical costs by street.  This contract
contains no optimization based on structural zeros after a board card is
revealed.

Let
\[
 K=R^2,\qquad H=\binom{4R}{2},\qquad
 b_f=4,\qquad b_i=4,\qquad b_{\rm bool}=1.
\]
The model-input byte declarations are
\begin{align*}
 I_{\mathsf{pre}}
   &=I^{\rm public}_{\mathsf{pre}}+b_fPK,\\
 I_{\mathsf{post}_A}
   &=I^{\rm public}_{\mathsf{post}_A}+b_fAH
     +b_i\one_{A<P}.
\end{align*}
Only live players contribute exact-hand postflop ranges.  The last term is an
immutable reference to one folded-player summary stored at its dependency
anchor; it is not an inlined summary.  Poker creates a new anchor exactly when
the summary dependencies change: on a fold event or a public-street
transition, following \texttt{MHA\_model.md} and
\texttt{folder\_impact.md}.  Every descendant decision references that
immutable anchor until the next such event.  A street transition therefore
refreshes poker-owned input data; it does not create a street partition or
change the fixed $\mathsf{post}_A$ layout.  In particular,
$\mathsf{post}_P$ has no summary reference and never materializes a neutral
summary.

RB leaf completion is the only game-specific terminal boundary.  For poker,
\Obj{CompletionSpec} is the binding contract documented in the read-only
\texttt{/home/pablob/poker-gpu-evaluator/docs/api\_pbg.md}: the leaf owns the
required contiguous board, range-weight, dealt/contender, pot-stratum,
baseline, amount, and logical-seed fields in their declared dtypes.  The core
calls the sibling evaluator and extracts only posterior-mass and value rows
needed by the target algorithms; it must not reimplement equity, posterior, or
Monte Carlo completion locally.  Completion inputs, batching, outputs,
scratch, and backend workspace are part of the hard byte contract.

The preflop architecture is intrinsically defined on the ordinary quotient
$c:\{1,\ldots,H\}\to\{1,\ldots,K\}$, which is $1326\to169$ for the full
$R=13$ deck.  Thus
\[
 Y_{\mathsf{pre}}=K,\quad \varphi_{\mathsf{pre}}=c,\qquad
 Y_{\mathsf{post}_A}=H,\quad\varphi_{\mathsf{post}_A}=\operatorname{id}.
\]
Preflop model inputs and every materialized or retained dense current, old, and
reference policy/value output are exactly $K$-dimensional; no staging, storage,
or cache may expand them to $H$.  Postflop model inputs and every materialized
or retained dense current, old, and reference policy/value output are exactly
$H$-dimensional, including zero rows for board-blocked hands.  Normal mode may
retain only its selected scalar loss slices; that is a strict projection, not
an $H$-wide representation.  Crucially,
\[
  X_{\mathsf{pre}}=X_{\mathsf{post}_A}=H
\]
for RB posteriors, returns, advantages, and losses.  At preflop an exact-hand
loss term for $h$ simply uses model row $c(h)$; no duplicate $H$-dimensional
model output is retained.

\section{Stable row domains and owning objects}

Let $D_m$ be player decisions in partition $m$, $D=\sum_mD_m$, $L$ stopped
leaves, and $G$ sequential trajectories.  Sequential modes have one implicit
sampled edge per decision and allocate no separate action table.  In branched
RB, $A_m$ is the number of sampled outgoing player edges in partition $m$ and
$A=\sum_mA_m$.

A decision receives $(m,d)$ when its player occurrence is created.  A branched
player edge receives $(m,a)$ when its logical children are reserved, before any
physical model pack.  Reservation order is stable, and the $u$th action row is
aligned with the $u$th contiguous child.  Physical packing may split this work
but cannot alter an address, draw, or topology.

Rollout arenas and growing tables are chunked and append-only.  Their row
identities are logical integers, never pointers into reallocatable tensors.
After rollout, \Obj{SealRolloutStorage} in
\texttt{family\_scheduled\_rollout.tex} allocates exact contiguous destination
columns, copies stable spans once, validates the topology, and only then
releases source chunks.  This is an explicit phase: admission charges source
capacity, destination capacity, and bounded seal scratch simultaneously.  No
claim of zero-copy ownership transfer is part of the design.

\section{Compact topology}

\Obj{SequentialDecisionCSR} contains only
\[
 \mathtt{trajectoryPtr}[G+1],\quad
 \mathtt{decisionPartition}[D],\quad
 \mathtt{decisionRow}[D],\quad
 \mathtt{leafRow}[G].
\]
Decision owner/event/type live in the partition row.  Chance nodes do not
advance a player clock and need no backward row.  No sampled private profile
survives rollout: normal leaves already own exact terminal rewards.

\Obj{BranchedTreeSpan} contains int32
\[
 \mathtt{parent},\ \mathtt{childBegin},\ \mathtt{degree},\
 \mathtt{decisionPartition},\ \mathtt{decisionRow},\ \mathtt{leafRow}
 \quad [N].
\]
Sentinel $-1$ marks an inapplicable field.  Children of every node are
contiguous, so there is no $\mathtt{childNode}[E]$, duplicated child event, or
stored $\nu[E]$: $\nu=1/\mathtt{degree}$ is implicit.  At a player node the
action span has the same order as the target-eligible prefix of the child span.
Normally that prefix is complete.  Only at a refilled root it has length
$N_0(\varnothing)<N_+(\varnothing)=\mathtt{degree}[0]$; added root children
have no root action rows, while decisions below their subtrees remain ordinary
learning rows.  Two scalar int32 metadata values store
$\mathtt{rootTargetDegree}=N_0(\varnothing)$ and
$\mathtt{preRefillNodeCount}=|\mathfrak S_0|$.  Final root transition mass is
$1/N_+(\varnothing)$ and descendant decision masses use recomputed final path
mass; root targets alone use the protected prefix.

Thus the finalized topology sizes are exactly
\[
 T_{\rm seq}=b_i(2D+2G+1),\qquad
 T_{\rm branch}=6b_iN+2b_i.
\]

\section{Write times and lifetime schedule}

The generated reach is written once at its last necessary destination:
natural decision input at player-node creation, exact RB leaf reach at stopped
leaf creation.  Chance-only reaches and mutable public states live only until
their descendants are materialized.  Once a processed parent has committed
all children, its mutable public state and active reach/profile are released;
only compact topology fields remain.  A stopped leaf releases the same
payload immediately after its immutable reward or completion row is written.
No target builder replays a path to reconstruct reach, and no $[N,P,X]$ reach
memo exists.

\begin{longtable}{p{0.14\textwidth}p{0.40\textwidth}p{0.38\textwidth}}
\toprule
Phase & Resident & Released before next phase \\
\midrule
\endhead
Rollout & read-only $\theta_k$; mutable public states; occurrence arena; queues; active reaches/profiles; growing chunked input/old/action/leaf tables; transient KKT path factors and queue-cost forecast; one bounded physical pack & each physical output immediately; then queues, active rows, mutable states, KKT path factors, and queue-cost scratch \\
Seal & rollout source-chunk capacities; exact contiguous topology/input/old/action/leaf destinations; bounded copy/scan scratch & source chunks and seal scratch after synchronized validation \\
Targets & compact topology and protected-root metadata; partition input/old tables; leaf table; final target arrays; one completion microbatch; sequential carries or one prebounded branched slot arena containing posterior/value moments and transient vector-value/$C/\Delta$ rows & every extra completion result immediately; reduced slots immediately; then leaf table, topology, frozen control predictions, validity flags, and target scratch \\
Optimization & immutable training storage; optional selected reference caches; model/reference/optimizer; flat gradient SUM buffer; one reusable bounded physical-subspan arena & each subspan's graph, gathers, reductions, and uncached reference output immediately after backward; then reference cache and training storage after the final optimizer step \\
\bottomrule
\end{longtable}

Synchronous training needs no frozen copy of $\theta_k$: parameters remain
read-only until all GPUs have fixed targets and enter the first optimizer step.
A future overlapped rollout/optimization pipeline would require an explicit
snapshot and a different lifetime proof; it is not part of these algorithms.
``Release'' means the last owning reference is gone and the storage can be
reused.  Allocator reserved bytes and backend workspaces are measured
separately; a Python name deletion alone is not a memory event.

\section{Old implementation pattern versus new invariant}

\begin{longtable}{p{0.30\textwidth}p{0.36\textwidth}p{0.25\textwidth}}
\toprule

\midrule
\endhead
Full-capacity or global-$H$ decision reach buffers & Append the natural partition input at decision creation & Removes unused capacity and the unnatural preflop $K\to H$ expansion. \\
Root cache followed by recursive \texttt{recompute} into an all-node reach memo & A generated decision or leaf reach is written once to its last consumer & Removes replay compute, Python traversal, and $[N,P,X]$ memo. \\
Global maximum action axis and padded target tensors & Branched sampled edges use CSR; sequential sampled edge is implicit & Storage and gathers scale with sampled edges, not $D E_{\max}$. \\
Whole logical-batch outputs retained while children are created & Reserve all logical addresses first; forward, materialize, and release one physical subspan at a time & Bounds inference staging without changing topology or RNG. \\
All-node sequential topology including chance nodes & Decision-only trajectory CSR & Reverse work scales with decisions; player clocks remain exact. \\
Separate sequential value, advantage, and return arrays plus repeated posterior rows & Retain one $\mathtt{lambdaReturn}$, derive $V/A$, and reference one completion posterior per trajectory/player & Removes exact algebraic duplicates, not estimator information. \\
Stored branched parent posterior and child posterior & Retain child posterior; derive the parent mean in the node loss & Saves $b_f\sum_mD_mX_m$. \\
Mandatory frozen rollout-model clone & Keep $\theta_k$ read-only until synchronous optimization starts & Removes one model snapshot in the specified lifecycle. \\

\end{longtable}

The design does not prohibit all recomputation.  Cheap loss-time expressions
($\widehat V=\mathtt{lambdaReturn}$,
$\widehat A=\mathtt{lambdaReturn}-V^{\theta_k}$, and a branched
parent-posterior mean) are deliberately derived, and a reference forward may be
recomputed when its cache would reduce safe decision capacity.  What is
forbidden is replaying discarded rollout state or changing an estimator to
save bytes.

\section{Byte formulas}

Let $Y_m=|\mathcal Y_m|$ be the partition's natural model-row width, and let
\[
 M_{\rm post}^{\rm seq}=b_f\sum_{(i,p)\in\mathcal U}X_{m(i,p)}
\]
be the sequential posterior pool for the set $\mathcal U$ of trajectory/player
pairs that own at least one sampled decision.  Define
\begin{align*}
 C_{\rm normal}&=3b_iD,\\
 C_{\rm seqRB}&=3b_iD,\\
 C_{\rm branch}&=b_iD+b_i\sum_m(D_m+1)+b_iA,\\
 M_{\rm sample}&=b_{64}|\mathcal M_+|+
   \sum_{m\in\mathcal M_{\rm nonuniform}}D_m(b_{64}+b_i).
\end{align*}
Excluding optional reference caches and game-owned summary anchors, the compact
training stores are
\begin{align*}
 M_{\rm normal}
  &=\sum_mD_m(I_m+3b_f)+C_{\rm normal}+M_{\rm sample},\\
 M_{\rm seqRB}
  &=\sum_mD_m(I_m+2b_fY_m+b_fX_m)
    +M_{\rm post}^{\rm seq}+C_{\rm seqRB}+M_{\rm sample},\\
M_{\rm branchRB}
  &=\sum_mD_m(I_m+b_fY_m+b_fX_m+2b_f+b_i+b_{\rm bool})\\
  &\quad+\sum_mA_m(b_fY_m+2b_fX_m)
    +C_{\rm branch}+M_{\rm sample}.
\end{align*}

Let $B_{\rm reach}=b_f\sum_{p\in\mathcal P}|\mathcal X_p|$ and let $C_L$
be completion-public-input bytes per RB leaf.  Leaf stores are
\[
 M_L^{\rm normal}=L(b_i+b_fP),\qquad
 M_L^{\rm RB}=L(b_i+b_{64}+C_L+B_{\rm reach}).
\]
The first int is terminal kind; topology owns the leaf address.

Hard accounting uses allocated capacities, not logical payload alone.  For
every chunked column $e$, let $\operatorname{cap}(e)$ be its allocated row
capacity and $b(e)$ its complete schema bytes per row, including alignment.
Define
\[
 M_{\rm chunks}=\sum_e\operatorname{cap}(e)b(e)
   +M_{\rm chunk-header}+M_{\rm allocator-slack}.
\]
The immutable schema, rather than a handwritten field count, generates this
sum and is shared by allocation, prediction, and ledger validation.  It must
include separate logical RNG address/key components, log weight, status,
root/ordinal, table addresses, and every mode-specific field.  Appending one
row first transactionally admits the next chunk's full capacity.

Let $S$ be worst-case mutable public-state bytes per resident state,
$F_{\rm state}$ the maximum number of simultaneously resident mutable public
states (queued, evaluating, or being chance-closed), $Q_{\rm cap}$ allocated
queue-handle capacity, $C$ maximum live sequential trajectories,
$M_{\rm summary}$ the game-owned immutable summary-anchor store, and
\begin{align*}
 M_{\rm state}&\leq F_{\rm state}S,\\
 M_{\rm queues}&=b_i(Q_{\rm cap}+2|\mathcal M|),\\
 M_{\rm active}(C)&=C(B_{\rm reach}+b_iP+2b_i).
\end{align*}
Thus state capacity follows the live-frontier high-water mark, not total
generated occurrences $N$; completed occurrences retain only their bounded
arena/topology metadata.  Let $R_{\mathsf m}$ be the mode's exact sealed
input, metadata, and old-output fields before targets; let $M_{\rm grad}$ be
the one flat fp32 gradient SUM buffer, $M_{\rm collective}$ its fixed reduction
workspace, and $M_{\rm index}=b_i\max_m B_m^{\rm cap}$ one reusable index-only
draw buffer sized by the statistical time-budget caps; and let
$W_{\rm infer}$, $W_{\rm seal}$, $W_{\rm completion}$, and
$W_{\rm backward}$ be calibrated hard transient bounds.

For optimization, $W_{{\rm train},m}(J;\mathcal C)$ is the
allocator-reserved high-water increment for one physical decision-index
subspan $J$ in partition $m$ with reference-cache set $\mathcal C$.  It includes
only that subspan's input/target/cache gathers, branched action rows, uncached
reference output, current-model activations, exact-loss reductions, AMP
temporaries, and backend workspace.  Define
\begin{align*}
 M_{\rm opt}^{\rm base}
  &=M_{\rm static}+M_{\mathsf m}+M_{\rm summary}+M_{\rm refcache}\\
  &\quad+M_{\rm grad}+M_{\rm collective}+M_{\rm index},\\
 W_{\rm train}
  &=\max_{m,J\ {\rm executed}}W_{{\rm train},m}(J;\mathcal C),\\
 W_{\rm refbuild}
  &=\max_{m\in\mathcal C,J\ {\rm built}}
    W_{{\rm refbuild},m}(J;\mathcal C),
\end{align*}
where $W_{\rm refbuild}=0$ when $\mathcal C=\varnothing$.
Because every subspan is backwarded and released before its successor, neither
statistical counts $B_m$ nor different partitions are added in $W_{\rm train}$.
Activation checkpointing is not part of the default bound; it is admitted only
as a separately measured physical-shape variant when its recomputation improves
end-to-end spots/second, or when no uncheckpointed singleton fits.
Then
\begin{align*}
 M_{\rm rollout}
  &=M_{\rm static}+M_{\rm state}+M_{\rm chunks}^{\rm high}
    +M_{\rm queues}+M_{\rm active}(C)+M_{\rm summary}+W_{\rm infer},\\
 M_{\rm seal}
  &=M_{\rm static}+M_{\rm chunks}^{\rm final}+T_{\mathsf m}
    +R_{\mathsf m}+M_L+M_{\rm summary}+W_{\rm seal},\\
 M_{\rm targets}
  &=M_{\rm static}+T_{\mathsf m}+M_{\mathsf m}+M_L+M_{\rm summary}
    +W_{\rm completion}+W_{\rm backward},\\
 M_{\rm optimization}
  &=M_{\rm opt}^{\rm base}+\max\{W_{\rm train},W_{\rm refbuild}\},\\
 M_{\rm peak}&=\max\{M_{\rm rollout},M_{\rm seal},M_{\rm targets},
 M_{\rm optimization}\}.
\end{align*}
No mutable all-node public-state store appears in target or optimization
phases.  Objects with disjoint lifetimes are not added.  Admission uses
allocator-reserved/NVML bytes, not only live tensor bytes.  With usable device
capacity $M_{\rm device}$ and intentionally unused guard $M_{\rm guard}$, every
cache choice and physical plan must satisfy both
\[
 M_{\rm opt}^{\rm base}+\max\{W_{{\rm train},m}(J;\mathcal C),
 W_{{\rm refbuild},m'}(J';\mathcal C)\}
 \leq M_{\rm hard}:=M_{\rm device}-M_{\rm guard}
 \quad\textnormal{for every executed training or cache-build subspan}.
\]

On a 2080 Ti constrained to 10.5 GiB usable VRAM, take initially
$M_{\rm guard}=0.75$ GiB and hence $M_{\rm hard}=9.75$ GiB.  The guard covers
measurement error, allocator fragmentation, and unmodeled backend-workspace
variation.  The ceiling may be raised only after
each phase's reserved-byte high-water mark is stable across representative
iterations; an OOM is not a calibration method.

\section{Memory-only sequential root-width control}

Normal and sequential-RB runs choose a common per-GPU root width $G_k$ with
Algorithms \Obj{ChooseSequentialRootWidth} and
\Obj{ObserveSequentialMemory} in
\texttt{sequential\_memory\_control.tex}.  There is intentionally no
player-node or throughput target in v1.  The controller solves the simpler
root-only analogue of choosing $\beta(\varnothing)$ and then fixing
$\beta(\sigma)=1$ below the root: it selects the largest lagged width whose
upper prediction fits every physical phase, then applies conservative growth
hysteresis.

The predictor is schema-derived and phase-specific.  It combines exact fixed
bytes with one-sided per-root estimates for realized decisions, occurrences,
leaves, chunk capacity/slack, summary anchors, seal overlap, posterior rows,
and calibrated workspace.  It uses completed prior iterations only; $G_k$ and
all root keys are frozen before any current draw.  Ranks use an all-reduced
minimum safe width so synchronous work and collective order agree.  Unsafe
evidence decreases width immediately, whereas an increase is capped and
requires a run of successful covered iterations.  State and calibration are
checkpointed.

This is a capacity controller, not a geometry rejection rule.  Neither it nor
\Obj{SafeAdmit} may truncate, discard, reroll, or replace already selected
roots.  \Obj{SafeAdmit} only limits concurrent live frontier work.  If the
declared transaction for a chunk, seal, completion, or singleton learner
subspan cannot fit, the run checkpoints and stops cleanly; it does not alter
the conditional sampling law.  Optional reference caches are excluded from
root feasibility and may be admitted later only when both cache construction
and training fit.  Consequently the empty-cache path is always the safety
fallback.

At every phase boundary, terminal local failures participate in one declared
common-order control agreement before any later collective.  If any rank
fails, all ranks release the current partial/sealed store and terminate from
the last completed checkpoint.  A rank must never skip a collective while
healthy peers enter it, and no failed current iteration is retried.

\section{Implementation order and acceptance gates}

The recommended order is:
\begin{enumerate}[nosep]
  \item immutable schemas, exact capacity ledgers, stable decision/leaf reach
  ownership, and complete removal of reach replay;
  \item decision-only sequential topology, contiguous branched child spans, and
  logical reservation before bounded physical forwards, followed by explicitly
  budgeted exact sealing;
  \item exact target deduplication while retaining old outputs at natural model width;
  \item the memory-only sequential root-width controller and checkpoint state;
  \item per-partition reference-cache selection, including build admission, and
  direct flat gradient views;
  \item index-only statistical draws followed by plan--gather--backward--release
  physical subspans, calibrated separately by partition;
  \item only then tune queue thresholds, statistical stratum counts, and the
  small warmed physical-shape sets from measured reserved bytes, kernel
  occupancy, and end-to-end spots/second.
\end{enumerate}

Acceptance requires randomized small-PBG equality tests against direct
\texttt{core\_math.tex} formulas for all three modes, including $\lambda=0,1$,
one/many branched children, zero posterior mass, and every production-v1 loss.
It also requires per-phase allocated/reserved peaks, per-partition
time/physical-byte curves, tail-subspan tests, and fixed-seed rollout, target,
and optimization timings.  Statistical counts $B_m$ remain arbitrary positive
integers; only physical shapes are calibrated, and no universal multiple-of-32
rule is imposed.  For one fixed sampled index vector, an unsplit reference
calculation and every legal multi-subspan plan must produce the same
$\alpha_m/B_m$-normalized objective and gradient within the declared arithmetic
tolerance, including a one-row tail and cache-versus-recompute reference paths.
Sealing tests must force multiple source chunks and verify exact destination
extents, stable row/topology order, and a measured peak no larger than the
declared source-plus-destination-plus-scratch transaction.  Controller tests
must cover cold start, immediate decrease, delayed/capped increase, multi-rank
minimum, checkpoint resume, underestimated geometry, and clean pre-draw or
singleton failure with no reroll.  Poker tests must assert that all stored
preflop model inputs/outputs/caches have width $K$ (169 for $R=13$), all stored
postflop model inputs/outputs/caches have width $H$ (1326 for $R=13$), and RB
posteriors/targets retain the canonical $H$ exact-hand order in both cases.
No postflop-street specialization should be
added without a separate controlled experiment showing a material end-to-end
gain at equal sampled spots, identical estimators/losses, and no loss of safe
decision capacity; the current design intentionally contains none.
