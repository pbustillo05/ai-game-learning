# Queued mode contracts

Status: Phase 1 contract, generated by `pbg.queued.contracts`.

## Closed semantic identity

A mode is exactly one row of:

```text
training_regime   self_play | best_response
rollout_mode      sequential | branched.fixed | branched.KKT
private_estimator sampled | rao_blackwell
```

The Cartesian product has twelve rows. `root_count`, `n_replica`, rank
ownership, device count, precision, and learner batch shape are execution
dimensions, not mode axes. Old aggregate names are not accepted by the queued
package.

`ModeSchema` is immutable data. All rows are produced by one generator; there
is no mode class hierarchy or runtime engine selector. `mode_schema` accepts
only the closed axis values and rejects every other spelling or combination.

The sampled branched rows are deliberate negative-control research modes.
They use one joint private profile for a complete tree, intentionally correlate
siblings, and exist to demonstrate that the biased estimator is a bad idea.
No sequential or Rao--Blackwell row uses this law.

## Generated differences

| Condition | Applicable schema data |
|---|---|
| best response | `role_selector`, frozen-profile identity, response initialization, role hook |
| sampled | scalar output domain, retained sampled private state, sampled showdown leaf, return carrier |
| Rao--Blackwell | private-state output domain, completion controls, range/seed leaf, mass/moment carriers, posterior action target |
| branched | output-partitioned action rows, public T/C heads and targets, degrees/path mass, trace/cost/delta carriers, ragged learner index |
| fixed | `fixed_beta` control |
| KKT | `kkt_controller` control |

Inapplicable data is absent from the tuple of fields and from applicable
configuration. There are no nullable columns. For example, a sampled leaf has
`combo_ids` and no `range_weights`, `seed`, or `selected_player`; a
self-play RB leaf has `range_weights` and `seed` but no `selected_player`.

## Partitions and conversions

The generic queued package does not name poker streets, cards, hands, or seats.
A game hook supplies an immutable `PartitionContract` containing:

- nonempty, unique input, output, and folded partitions;
- one and only one output mapping for every input partition;
- positive fixed widths;
- an explicit list of endpoint conversions.

The NLHE hook must declare:

```text
input  = {pre} union {post_A : 2 <= A <= P}
folded = {pre, post}
```

For sampled rows, `output={all}`, `size[all]=1`, and every input maps to
`all`. For RB rows, `output={pre,post}`,
`size[pre]=R^2`, `size[post]=2R(4R-1)`, `pre -> pre`, and every
`post_A -> post`. The sole poker output conversion is deterministic FP32
`post -> pre` H-to-K reduction. It sums mass and moment before
conditionalization.

Sequential action rows use the input partition and align one-to-one with
learner sigma rows. Branched action rows use the output partition and preserve
ragged target-eligible child spans.

## Owner vocabulary

Every schema declares the same owner names. Fields vary only by the generated
conditions above.

| Owner | Index/partition | Lifetime |
|---|---|---|
| `FamilyWork` | player node / input | root commit through align-and-seal |
| `SigmaHead` | learner player / input | model commit through final backward |
| `ActionHead` | action / input or output | model commit through final backward |
| `Leaf` | leaf | leaf commit through completion |
| `Topology` | structural node | topology packet through `LayerPlan` |
| `TopologyChild` | structural edge | topology packet through `LayerPlan` |
| `FoldedRanges` | folded partition | fold event through align-and-seal |
| `QueueMetadata` | input partition | root commit through queue drain |
| `LayerWork` | output partition | completion through target publication |
| `SigmaTarget` | learner player / input | publication through final backward |
| `ActionTarget` | action / input or output | publication through final backward |
| `LearnerIndex` | learner player / input | align-and-seal through final backward |

The Phase 1 field tuples are contractual vocabulary, not allocations. Phase 2
turns them into aligned `SoASchema` owners and proves byte/lifetime accounting.

## Opaque game hooks

Generic queued code sees opaque request/result objects through these operations:

```text
partitions
initial_roots
model_input
sample
transition
folded_summary
leaf_to_layer_work
role                    # best response only
```

`commit`, queue scheduling, topology publication, target execution, learner
sampling, and optimizer transition are generic engine operations and are not
game hooks. The hook protocol deliberately exposes no poker type and queued
core imports neither `pbg.core` nor `pbg.games.poker`.

Poker owns profile sampling, action/chance label construction, folded
summaries, policy composition, and state transitions. Its single
`leaf_to_layer_work` hook dispatches to the exact evaluator-v2 showdown or
completion operation selected by the immutable schema. The contract version is
checked at the consumer boundary; no compatibility facade or fallback is
allowed.

## Replica axis and physical compatibility

All ranks have the same lane IDs. Lanes share:

```text
physical schema signature, game geometry, partitions, capacities,
root_count, schedule, private estimator
```

Each lane owns:

```text
semantic mode, weights, loss coefficients, controller state, tails,
logical RNG, failures, learner permutations
```

Fixed and KKT branched lanes may share one execution group only when training
regime, estimator, partition contract, capacities, and every owner field
signature match. Their semantic `ModeSchema` rows and lane-local controller
states remain distinct. Sequential and branched rows, sampled and RB rows, or
self-play and best-response rows are physically incompatible.

`n_replica=1` is the ordinary path. Inactive lanes create no padding and draw
no RNG.

## Capacity contract

The immutable public capacity manifest supplies capacities by partition for
player nodes, learner player nodes, actions, folded ranges, leaves, topology
nodes, and topology edges. It also bounds every family/chance/completion pack,
target arena, learner sigma/action pack, packet, scratch allocation, library
workspace, evaluator workspace, and guard.

Before allocation, Phase 2 validates the manifest against:

```text
(P,S,R), deck fit, SP+3P-S+1 history bound, ModeSchema,
partition widths, root_count, n_replica, beta_max,
hardware memory/token limits, external workspace bounds
```

Capacities never grow during a run. Hardware profiles calibrate public
capacity and launch values; they do not select a storage engine or alter a law.

## Static isolation

`pbg.queued.static_gates` parses imports and string literals without importing
production modules. The Phase 1 gates prove:

- queued code imports neither old core nor poker;
- queued code contains no aggregate legacy mode string;
- no accepted production root can transitively reach both engines.

Production does not import `pbg.queued` before cutover. Comparison tests invoke
the two engines independently and never pass representations between them.
